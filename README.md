# BHH PDF 转 Word（离线单文件版）

一个原生 C++/Win32 桌面小程序。所有文件仅在本机处理，不调用网络接口。

开发与验收规则见 [开发文档](DEVELOPMENT.md)，版本修改记录见 [开发日志](CHANGELOG.md)。

- 使用原创 `BHH` 品牌图标，并采用深蓝企业级窗口视觉设计。

## 功能

- 选择或拖入 PDF，设置 `.docx` 保存位置。
- 自动模式：固定使用内置离线可编辑引擎，Word 高保真模式需手动选择。
- 智能可编辑模式：按 PDF 坐标重建段落、字号、间距和分页；检测表格并创建真实 Word 表格；将图片作为独立对象插入。
- 数字与字体编码修复：识别 PDF 子集字体常见的私有区数字编码，转换为标准 Unicode；随后核对日期、前导零、负数、小数、千分位金额和百分比。
- 数字校验以"数值是否还在"为准：核对时会扫描正文、表格、嵌套表格、文本框和页眉页脚，并把 `10,000` 与 `10000`、全角与半角视为同一数值。只有当某些数值在 Word 中完全找不到且超过容差（不同数值数的 2%，至少 3 个）时才判定转换失败；仅仅是出现次数变少（合并单元格、重复表头都会造成这种差异）只作为提示，文件照常输出。
- 宽表优化：自动压缩 5 列以上表格的字体、单元格边距和行距，移除错误的固定行高，避免一行被撑满整页。
- 几何表格恢复：当 PDF 错误声明合并单元格时，依据真实表格线和字符坐标重新分列，避免收费金额、比例和依据文字丢失。
- 表格颜色恢复：读取 PDF 矢量背景填充，尽量保留蓝色表头和分类单元格。
- 混合页面方向：同一 PDF 内的横向页和纵向页分别写入对应的 Word 节。
- 图片表格转为真实表格：自动和智能可编辑模式会检测扫描图片中的横竖表格线，按 OCR 词框坐标重建 Word 行列与矩形合并单元格；支持整页扫描表格及文字页中独立插入的图片表格。表格单元格可直接修改、增删行列，不再只输出扫描图加文字层。抬头、落款等表格外内容保留原图。
- 拍照折皱表格：常规直线识别失败时，追踪弯曲网格、校正行列和阴影，再用随程序打包的 PP-OCR 模型离线识别单元格；手机照片的像素尺寸不会直接当成 Word 纸张尺寸，恢复为 A4 表格。侧边印章作为独立图片保留。
- 离线 OCR：调用 **Windows 自带的离线 OCR 引擎**识别，不上传文件，不下载识别模型。识别前去除表格长线；空数字单元格会局部重识别。没有检测到可靠网格时保留扫描图并添加可搜索文字层。
- 印章独立分离：整页统一提取红色印章，圆环和五角星保留在同一个透明浮动图片中；每个原始印章只插入一次。落款公司名称和日期写为独立可编辑文字，印章可以单独选中、移动或删除。
- OCR 文字修正：Windows 引擎会把小数点认成全角逗号、把连字符认成汉字「一」、并在汉字之间插空格。这些是确定性替换，转换时按规则还原——实测一份真实报价单，26 个金额和 26 个图号全部还原正确。识别顺序按词框坐标重排，避免整列文字被串成一行。
- 缺少语言包时如实报告：目标机器没装中文 OCR 语言包时，会列出已装语言并指出在「设置 - 时间和语言 - 语言和区域 - 可选功能 - 光学字符识别」里安装，然后退回纯图片结果，不会假装识别过。
- 扫描件识别：逐页检查源 PDF 有没有文字层，没有的页会在转换完成时明确列出。数字和字形校验对这类页面恒为满分，不加这一步就会静默交付一份"看着正常、其实没有一个字"的 Word。
- 图片按可用区缩放：版式引擎会把整页扫描图按整张纸的尺寸插入，连页边距一起占满，Word 里每页都会溢出到下一页。写出前统一把超出可用区（页面尺寸减四边页边距）的图片等比缩小，保证一页对应一页。
- 图片体积优化：版式引擎把 PDF 里的 JPEG 一律重编码成 PNG，扫描件因此膨胀数倍。输出前会把较大的照片类 PNG 转回 JPEG（质量 82，带透明通道或非 RGB/灰度的图片跳过），体积明显下降时才替换，并在替换后重新打开校验，确保文件可用。实测两页扫描件由 5.4 MB 降到 1.3 MB。
- 精准版式模式：将每页离线渲染为图片，并为每一页分别保留横向或纵向页面尺寸；外观稳定但内容不可编辑。
- Word 高保真模式：使用本机 Microsoft Word 的 PDF 重排能力，适合复杂排版。
- 支持中文路径、长路径、覆盖确认和转换状态提示。

## 能力边界

- 智能可编辑模式会尽量重建阅读顺序、文本位置和表格结构，但 PDF 本身不保存 Word 的段落/表格语义，复杂多栏、合并单元格、特殊字体和浮动对象仍可能需要人工调整。
- 精准版式模式中的每页是高清页面图像，文字不能直接编辑。
- Word 高保真模式需要 Microsoft Word 2013 或更高版本。
- 图片表格重建依赖可追踪的横竖表格线；无线表格、严重模糊或遮挡、复杂不规则合并区域可能保留为图片。常规扫描件使用本机 OCR 语言包，并由内置离线模型按单元格复核数字及含数字的规格；仅接受两次高置信度一致的修正，保留空白图号。折皱拍照表格另有校正和离线识别流程。
- 数字复核支持多位小数及误读为汉字、符号的金额，不用数量乘单价来补造数值。识别分歧或数量、单价、金额关系异常会提示具体页码和单元格；OCR 仍需人工核对，不能保证任意扫描件零错误。
- 转换失败时会显示数字缺失或字体编码错误的具体原因，不再只显示笼统错误。
- 转换成功但存在少量存疑之处（数字出现次数变少、仍有无法确定编码的字符、某些页只能保留为图片）时，会在"转换完成"提示中一并列出，供人工复核。

## 构建

在 PowerShell 中运行：

```powershell
.\build.ps1
```

构建环境：MSVC C++ 编译器、PyInstaller、pdf2docx/PyMuPDF，以及本机离线 Poppler 工具。最终发布包不要求用户安装 Python。

输出目录：`dist\PDFToWord-Single.exe`。智能可编辑引擎和 Poppler 已嵌入主程序，用户只需复制这一个 EXE；转换期间程序会把内置引擎释放到独立临时目录，并在退出时清理。

## 离线自测

数字校验与 DOCX 扫描逻辑可以脱离 `pymupdf` / `pdf2docx` 单独运行，只需 `python-docx`：

```powershell
python .\tests\test_numeric_check.py
python .\tests\test_scan_tables.py
python .\tests\test_cell_ocr.py
```

## 命令行测试接口

```powershell
.\dist\PDFToWord-Single.exe --convert input.pdf output.docx --engine image
```

`--engine` 可选值：`editable`、`image`、`word`、`auto`。`auto` 固定使用经过数字校验的内置智能可编辑引擎，不再因检测到 Word 而切换到不可靠的 PDF Reflow；`word` 仅在用户明确选择时调用。
